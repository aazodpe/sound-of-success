Data Preparation and Exploratory Analysis

Answering the question at the centre of this project needs three different kinds of evidence about the same songs: what a recording measurably is, how it actually performed, and what listeners say about it. No single source carries all three, so four were gathered and joined.

Where the data came from, and why

A song's fate is not recorded in any one place. The qualities of the recording itself live with the streaming platforms that analyse audio; its commercial performance lives with the charts; and the way people actually talk about music lives in the words listeners volunteer. Each source below was chosen to supply one of those pieces, and the sources were deliberately picked so that two of them overlap on the same songs — without an overlap it would be impossible to ask whether what a song sounds like has anything to do with how it did.

SourceHow it was obtainedWhat it contributesSize
Spotify audio features

Qualitative and quantitative, labelled and unlabelled. The audio features are quantitative and carry genre labels; the chart history is quantitative and supplies a binary outcome label; the listener tags are qualitative free text with no labels at all. Between them the project has material for both supervised and unsupervised work.

The API calls

Deezer — developers.deezer.com/api

Deezer publishes an open API that needs no key and no registration. Two endpoints were used. The first returns the current chart for a given editorial genre, which produces a genre-balanced sample rather than only whatever happens to be globally popular; the second returns full details for a single track.

Core endpoint: https://api.deezer.com/chart/{genre_id}/tracks

GET https://api.deezer.com/chart/132/tracks?limit=100

MusicBrainz — musicbrainz.org/doc/MusicBrainz_API

MusicBrainz is an open music encyclopedia whose entries are annotated with tags written by listeners. It requires no key but enforces a strict rate limit of one request per second and asks that callers identify themselves in the user agent, both of which the collection script respects.

What the data looked like before and after

Nothing here arrived ready to use. The sections below show a small slice of each dataset as it was received and as it ended up, with the reasoning for every change in between.

Spotify audio features

The work in between removed 7,016 of the original 32,833 rows, leaving 25,817 songs with no missing values anywhere. Five rows were missing a track name or artist outright and were dropped, since neither can be inferred. A further 4,476 rows were exact duplicate track identifiers created by the one-row-per-playlist structure, and 2,533 more were the same song appearing again as a remaster, a live version or a re-release — these were collapsed by normalising titles and artists down to a comparable key, keeping the most popular version of each. One record listed a tempo of zero beats per minute, which is not something a recorded song can have, and one ran outside the half-minute to fifteen-minute window that separates songs from interludes and DJ mixes. Both were removed rather than repaired, because a value that cannot exist carries no information worth recovering.

Three new banded variables were then added by discretisation: a four-level popularity band, a four-level tempo band, and a four-level duration band, along with a binary label marking songs scoring sixty or above. A second copy of the file was written with every continuous audio measure rescaled to run from zero to one, since methods that work by measuring distance would otherwise let tempo, which runs into the hundreds, drown out danceability, which never exceeds one.

Billboard Hot 100

The blanks turned out to be the most interesting thing in this file. A missing last_week value does not mean the value was lost; it means the song was not on the chart the previous week, which is to say it had just debuted. Deleting those rows would have thrown away every chart debut in sixty-eight years, and filling them with an average would have invented a history that never happened. They were instead flagged with an explicit debut indicator and coded as position 101, a value that is numerically sensible and literally true: outside the Hot 100. Twenty-nine duplicated week-and-position entries were removed, titles and performers were stripped of stray whitespace, and a week-over-week position change was computed. The weekly table was then aggregated into 32,750 distinct songs, each carrying the best position it ever reached and the total number of weeks it survived.

Joining sound to outcome

Matching two catalogues that were never designed to be matched is imperfect, and being honest about that matters. Titles and artist names were lowercased, stripped of bracketed additions, featured-artist suffixes and punctuation, then compared. The 13.2 percent match rate is plausible rather than alarming: most of the songs carrying audio measurements are recent album tracks that were never chart candidates in the first place. Songs with no match are recorded as not having charted, with a peak position of 101 and zero weeks — again a real outcome rather than a hole in the data. The one caveat worth carrying forward is that this matching will miss some genuine chart entries whose titles differ between the two sources, which means the non-charting group contains a small number of songs that did in fact chart.

Deezer API records

The zeros were the trap here. 1,148 of the 1,806 tracks — nearly two thirds — came back with a tempo of zero, which does not mean the song has no tempo but that Deezer has not run its analysis on that recording. Leaving them alone would have dragged the average tempo of the collection down towards 45 beats per minute, a figure that describes nothing real. Each was instead marked with a bpm_known indicator and filled with the median of the tracks that do have a measurement, 128 beats per minute, so that later work can either use the filled values or restrict itself to the 654 genuine ones. Eight tracks outside the half-minute to fifteen-minute window were removed. The artist file needed far less: 1,251 unique artists, with follower counts banded into five audience sizes.

MusicBrainz listener tags

This is the only genuinely unstructured source in the project, and it was left as intact as possible on purpose. Tags were lowercased and stripped of punctuation so that Hip-Hop, hip hop and hip-hop stop being three different things, and duplicate pairs were collapsed, but no attempt was made to correct, merge or standardise the vocabulary itself. The messiness is the data. Artists missing a country, a type or a founding year kept those fields filled with an explicit Unknown rather than being dropped, since an artist with no recorded nationality still has perfectly usable tags.

Where this leaves the project

The exploration has already done something useful, which is to rule out the easy answer. If a song's success were legible in any single measured quality, the correlation figure above would have shown it, and it does not — nothing correlates with popularity above 0.14. At the same time, the data is plainly not structureless: music has changed in clear, consistent directions over sixty years, genres differ in their outcomes even while overlapping in their sound, and charting songs are measurably less instrumental and more cheerful than songs that never chart. What that combination suggests is that whatever signal exists lives in combinations of qualities rather than in any one of them, which is precisely the case for the methods that follow. The sharpest result so far, though, points somewhere else entirely: an artist's existing audience predicts how their songs perform roughly four times as strongly as any quality of the recording itself. That is a genuinely uncomfortable answer for a project asking what songs are made of, and testing whether it survives contact with the models is now the most interesting thing this data can be asked to do.
